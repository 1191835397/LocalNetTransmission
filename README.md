# 邻传 · LanLink

邻传是一个面向局域网的桌面文件传输工具，使用 React + TypeScript 构建界面，使用 Tauri 2 + Rust 提供本机文件访问、设备身份管理和 TLS 文件传输。两台设备通过局域网直接连接，无需云端中转。

当前版本为 **0.1.0，内部预览阶段**。已有自动发现、手动配对和单文件传输实现，但不应视为完成跨平台验收的正式发行版。macOS 真机、双机局域网互通以及安装包签名仍需另行验证。

## 当前功能

- 桌面启动后通过 mDNS 自动发现同一局域网内运行邻传的设备；“发现本地设备”按钮可重新发起发现，支持多网卡地址去重及离线移除。
- 从附近设备填入连接信息，或手动输入局域网 IPv4 地址和端口；核对完整证书指纹后进行双向确认配对。
- 保存可信设备、选择发送目标，以及撤销设备信任。
- 通过系统文件选择器或拖拽准备文件，每次发送一个普通文件。
- 接收端逐次确认接收，查看传输进度、取消任务和查询接收结果。
- 通过 TLS 传输，接收完成前核对文件长度与 SHA-256；同名文件自动加数字后缀，不覆盖已有文件。
- 配置设备名称、接收目录和监听端口，查看本机服务与诊断状态。

**尚未支持：** 文件夹传输、批量发送、暂停、断点续传和跨会话历史记录。可信设备列表不代表实时在线状态；浏览器预览不能进行真实设备发现或文件传输。

## 环境要求

### 通用依赖

- Node.js 22.12 或更高版本，推荐 Node.js 24 LTS；使用随 Node.js 安装的 npm。
- 桌面开发另需 Rust 1.90 或更高版本，以及 Cargo；静态检查需要 `clippy` 和 `rustfmt`。
- 首次安装依赖和构建需要联网下载 npm 包、Rust crates，打包时还可能下载平台打包工具。

### Windows

当前原生验证脚本面向 Windows；项目提供的 Rust 安装脚本仅支持 Windows x64。

- Visual Studio 或 Build Tools，安装“使用 C++ 的桌面开发”工作负载，包含 MSVC 和 Windows SDK。
- Microsoft Edge WebView2 Runtime。
- Windows 桌面构建使用 Rust MSVC 工具链。
- 配置及接收文件的存储位置需满足安全检查：本地 NTFS、支持持久 ACL；不支持 UNC 路径、网络映射盘或路径中的重解析点，例如目录联接和符号链接。

### macOS

- 配置的最低系统版本为 macOS 13.0。
- 自行安装 Rust 工具链及 Xcode Command Line Tools（可使用 `xcode-select --install`）。
- 身份存储使用系统 Keychain，文件存储检查要求本地 APFS/HFS 文件系统。
- 已有平台分支不等于完成真机验证；macOS 构建、签名与实际传输仍需验证。

Linux 尚未实现桌面应用所需的系统凭据存储，不属于当前可用的桌面传输平台。

## 快速开始

以下命令均在项目根目录执行。

### 1. 安装前端依赖

```sh
npm ci
```

项目包含 `package-lock.json`，使用 `npm ci` 按锁定版本安装依赖。

### 2. 准备并检查桌面环境

已安装 Rust 的环境可直接检查：

```sh
npm run doctor
```

Windows x64 如果没有 Rust，可以选择项目提供的安装方式：

```sh
npm run setup:rust
npm run doctor
```

`setup:rust` 下载并校验官方 Rust 安装器，将工具链安装到项目 `.tools/` 下，不修改系统 PATH。项目的桌面与 Cargo 包装脚本会优先使用该本地工具链；此命令不会安装 MSVC 或 WebView2。

`doctor` 检查 Node.js、Rust、Cargo 和本机 TCP 回环连接，在 Windows 上还检查 MSVC 与 WebView2。全部通过也不代表两台设备之间已经可以通信。

### 3. 启动桌面应用

```sh
npm run desktop:dev
```

该命令自动启动 Vite 并编译、打开 Tauri 桌面窗口，不需要另外运行 `npm run dev`。首次原生编译可能耗时较长。

### 仅预览前端界面

如果只开发界面，不需要准备 Rust 或原生构建环境：

```sh
npm run dev
```

打开 <http://127.0.0.1:1420>。浏览器模式不提供系统文件访问、真实设备配对或文件收发，不能替代桌面端验证。

## 构建与打包

### 前端静态资源

```sh
npm run build
```

先执行 TypeScript 检查，再使用 Vite 构建，产物位于 `dist/`。这不是桌面可执行程序或安装包。

可通过以下命令预览构建结果，地址为 <http://127.0.0.1:1421>：

```sh
npm run preview
```

### 桌面发行构建

```sh
npm run desktop:build
```

该命令自动构建前端、编译 Rust release 程序并调用 Tauri 打包。默认产物位置如下；指定目标架构或自定义 Cargo 输出目录时，路径会变化。

| 产物               | 默认位置                               |
| ------------------ | -------------------------------------- |
| Windows 可执行程序 | `src-tauri/target/release/lanlink.exe` |
| 桌面安装包/应用包  | `src-tauri/target/release/bundle/`     |

打包配置为当前平台的全部默认格式：Windows 通常生成 MSI/NSIS 安装包，macOS 通常生成 `.app`/DMG。请分别在对应系统准备构建环境；一次构建不会生成所有操作系统的安装包，成功编译也不代表完成签名或公证。

只编译桌面程序、不生成安装包：

```sh
npm run desktop:build -- --no-bundle
```

生成供本机调试验证使用的 debug 程序：

```sh
npm run desktop:build -- --debug --no-bundle
```

## 两台设备如何传输

1. 在两台设备上启动新版桌面应用，确保处于可互通的局域网，且本机服务正常运行。
2. 在“附近设备”查看自动发现的邻传设备，或点击“发现本地设备”重新查找。点击对方地址旁的“连接”，会填入下方配对表单；多网卡设备可选择对应网段的地址。
3. 通过对方的“设备与安全”页面或其他可信渠道核对完整 SHA-256 指纹，勾选确认后请求配对；对方也需核对请求方指纹并明确确认。广播中的名称、指纹未经认证，不能直接视为可信。找不到设备时仍可手动输入地址、端口和指纹，默认传输端口是 **TCP 53318**。
4. 发送端选择已信任设备，选择或拖入一个普通文件，确认发送。准备文件本身不会开始传输。
5. 接收端批准本次请求，等待长度与哈希校验完成，文件保存在设置中的接收目录，默认优先使用系统下载目录。
6. 如果显示“接收结果未知”，先查询接收结果并核实对方文件，避免直接重复发送。

注意事项：

- 自动发现使用 `_lanlink._tcp.local.` mDNS 服务（IPv4 组播 `224.0.0.251`、UDP 5353），只发现运行新版邻传的设备，不会逐个探测整个网段或列出所有电脑、手机、路由器。
- 自动发现会向所在局域网公告设备名称、平台、服务端口和公开证书指纹，不公告私钥或文件内容；请在可信的专用网络使用。更改设备名称后广播会更新，更改传输端口仍需重启。
- 附近设备按完整指纹去重并显示多个 IPv4 地址；mDNS 会周期性确认缓存及移除离线实例。列表可见不代表已经配对，也不保证业务连接可达；离线移除可能有延迟，不删除已保存的信任记录。
- 当前手动连接使用 IPv4 字面地址，仅接受私有、链路本地或回环地址，不支持域名、IPv6 或公网地址。
- 原生服务监听 IPv4 全部本机接口（`0.0.0.0`）；按需在防火墙中允许邻传应用、mDNS UDP 5353 及配置的 TCP 端口，并限制为可信的专用网络，不要关闭防火墙。组播不可用时可尝试手动连接，但 AP/访客网络隔离可能同时阻止单播。
- 监听端口可在 `1024–65535` 范围内修改，修改后需重启应用；开发页面的 `1420/1421` 端口不是文件传输端口。
- 配对不等于自动接收，每次文件接收仍需批准。已信任设备的地址、端口或身份改变时，撤销旧信任后重新配对。
- 只支持普通文件，不支持符号链接及路径中的链接目录。代码中的单文件大小上限为 64 GiB，这不是已完成该容量实机验证的承诺。

## 测试与检查

| 命令                   | 用途                                                     |
| ---------------------- | -------------------------------------------------------- |
| `npm test`             | 运行 Vitest 前端单元与组件测试                           |
| `npm run test:watch`   | 监听模式运行前端测试                                     |
| `npm run test:browser` | 运行 Playwright 浏览器测试，自动启动前端开发服务         |
| `npm run native:test`  | 运行 Rust 测试；默认跳过真实 mDNS、大文件等 ignored 用例 |
| `npm run native:check` | 运行 Clippy，视警告为错误                                |
| `npm run native:fmt`   | 检查 Rust 格式，不修改文件                               |
| `npm run format:check` | 检查前端、测试、脚本和配置的格式                         |

浏览器测试在 Windows 上使用已安装的 Microsoft Edge；其他平台使用 Playwright Chromium，需要先运行 `npx playwright install chromium`。发现界面测试使用 IPC 测试夹具，不能代替原生发现、文件传输和双机测试。

### mDNS 真实网络验证

以下用例默认忽略，需要在允许 mDNS 的专用 IPv4 局域网中显式执行：

```sh
node scripts/cargo.mjs test --manifest-path src-tauri/Cargo.toml discovery::tests::real_mdns_two_daemons_discover_refresh_rename_and_goodbye -- --ignored --exact --nocapture
```

它在同机启动两个发现实例，验证互相发现、刷新后重新发现、名称更新及正常退出后的设备移除；会发送真实 mDNS 广播，但使用合成身份，不读取或修改应用设置、私钥及信任记录。同机通过不代表双机网络、防火墙或 macOS 已通过验收。

### Windows 原生专项验证

`native:smoke` 和 `native:transfer` 会启动真实桌面程序、操作系统对话框，并可能修改本机应用设置及信任记录。请先退出正在使用的邻传，并在专门的测试环境运行，不要作为日常无副作用自检。

先构建 debug 程序，再按需执行：

```sh
npm run desktop:build -- --debug --no-bundle
npm run native:smoke
npm run native:transfer
```

这两个脚本默认使用 `src-tauri/target/debug/lanlink.exe`。验证已构建的 release 程序时，分别传入 `-- --release`。

`npm run native:memory` 会编译并运行原生大文件测试，采样 100 MiB/1 GiB 用例的进程内存，需要预留磁盘空间和执行时间。专项验证产物写入 `.tools/`；内存数据只覆盖同机 Rust 测试进程，不包含 WebView2，也不等于双机验收结果。

## 项目结构

```text
src/                  React 界面、原生桥接和类型定义
src-tauri/src/        Rust 身份、配对、网络传输、文件存储与设置
src-tauri/Cargo.toml  Rust 依赖及最低版本要求
src-tauri/tauri.conf.json
                      桌面窗口、前端构建入口和打包配置
scripts/              环境检查、工具链包装及原生验证脚本
tests/                前端单元、组件与浏览器测试
public/               前端静态资源
DEVELOPMENT_PLAN.md   分阶段开发计划与验收要求
```

应用设置和可信设备分别保存为 Tauri 应用配置目录下的 `settings.json`、`peers.json`。设备身份使用 Windows Credential Manager 或 macOS Keychain 存储；传输记录目前仅保留在当前会话中。

后续路线与验收要求见 [开发计划](DEVELOPMENT_PLAN.md)，其中规划项不代表已经实现。

## 常见问题

- **网页能打开，但不能选取本机文件或传输？** 浏览器模式仅供界面预览，请使用 `npm run desktop:dev` 或桌面构建产物。
- **提示缺少 Rust、链接器或 WebView2？** 先运行 `npm run doctor`，按环境要求补齐依赖；项目本地 Rust 不会自动加入普通终端 PATH，请优先使用 `npm run native:*` 和桌面脚本。
- **启动时提示端口占用？** `1420` 是严格固定的开发服务端口，不会自动换端口；先确认是否已有开发实例。传输服务默认使用 `53318`，可在设置中更换并重启。
- **已经配对但连接失败？** 检查对方应用是否运行、地址和端口是否变化，以及防火墙、访客 Wi-Fi 或 AP 隔离是否阻止互访。可信设备记录不会自动判断对方在线状态。
- **接收目录或配置读取失败？** 检查目录的本地文件系统类型、权限和路径中是否包含链接；配置损坏时不会自动覆盖为默认值，应先备份并根据错误提示处理。
